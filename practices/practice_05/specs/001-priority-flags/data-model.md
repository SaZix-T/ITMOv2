# Data Model: Приоритеты задач

**Feature**: `001-priority-flags` | **Date**: 2026-10-27

## Сущность Task (расширение)

Таблица `tasks` (SQLite, файл `data/taskflow.db` либо временный файл в тестах).

| Поле | Тип | Ограничения | Изменение в этой фиче |
|---|---|---|---|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | без изменений |
| title | TEXT | NOT NULL | без изменений |
| description | TEXT | DEFAULT '' | без изменений |
| completed | INTEGER | DEFAULT 0 | без изменений |
| due_date | TEXT | DEFAULT NULL | без изменений |
| created_at | TEXT | DEFAULT datetime('now') | без изменений |
| updated_at | TEXT | DEFAULT datetime('now') | без изменений |
| **priority** | **INTEGER** | **NOT NULL DEFAULT 1, допустимо 1–4** | **новое поле** |

### Правила

- `priority` принимает только целые 1, 2, 3, 4. Источник истины для допустимых значений — константа `PRIORITIES` в слое данных; маршрут использует ту же проверку.
- Значение по умолчанию — 1 (Low). Существующие строки получают 1 при миграции `ALTER TABLE ... ADD COLUMN priority INTEGER NOT NULL DEFAULT 1`.
- Значение вне диапазона, `NULL`, дробное или строка преобразуются к 1 при чтении (`normalizePriority`) и отклоняются с `400` при записи через API.
- Изменение `priority` обновляет `updated_at` так же, как любое другое изменяемое поле.
- Поле не влияет на сортировку `all()` и `search()` — порядок остаётся `created_at DESC`.

### Состояния и переходы

Приоритет не имеет собственного жизненного цикла: это атрибут задачи. Переходы, которые на него влияют:

| Событие | Результат для priority |
|---|---|
| Создание задачи без указания приоритета | 1 |
| Создание задачи с приоритетом 1–4 | указанное значение |
| Создание/обновление с некорректным значением | операция отклоняется (400), значение в базе не меняется |
| Отметка выполненной / снятие отметки | без изменений |
| Удаление задачи | поле удаляется вместе со строкой |

## Справочник Priority (не хранится в БД)

| Значение | Название | Цвет | CSS-переменная |
|---|---|---|---|
| 1 | Low | серый `#9ca3af` | `--prio-1` |
| 2 | Medium | синий `#4dabf7` | `--prio-2` |
| 3 | High | оранжевый `#f59e0b` | `--prio-3` |
| 4 | Critical | красный `#ef4444` | `--prio-4` |

Справочник дублируется в двух слоях: `public/app.js` (подписи и цвета меню) и CSS (переменные цвета). Дублирование осознанное: бэкенд не должен знать о представлении, а фронтенд не получает лишний запрос за статическим справочником.
