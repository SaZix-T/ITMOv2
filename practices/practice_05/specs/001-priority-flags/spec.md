# Feature Specification: Приоритеты задач

**Feature Branch**: `001-priority-flags`

**Created**: 2026-10-27

**Status**: Draft

**Input**: User description: "Возможность назначать задачам приоритет от 1 до 4, нажимая на иконку флажка рядом с задачей; иконка должна быть такого же цвета, как приоритет: 1 — серая, 2 — синяя, 3 — оранжевая, 4 — красная."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Назначение приоритета через меню флажка (Priority: P1)

Пользователь видит у каждой задачи иконку флажка и может назначить ей один из четырёх приоритетов: нажатие на флажок открывает небольшое меню с вариантами 1–4, выбор варианта сразу применяет приоритет к задаче.

**Why this priority**: Без возможности изменить приоритет фича не имеет смысла — это единственный способ ввода данных, ради которого всё делается.

**Independent Test**: Открыть список задач, нажать флажок у задачи, выбрать вариант 3, убедиться, что задача показывает приоритет 3 и он сохраняется после перезагрузки страницы.

**Acceptance Scenarios**:

1. **Given** в списке есть задача с приоритетом 1, **When** пользователь нажимает флажок и выбирает «3», **Then** задача получает приоритет 3, меню закрывается, список показывает новое значение.
2. **Given** меню приоритетов открыто, **When** пользователь нажимает на вариант, соответствующий текущему приоритету, **Then** приоритет не меняется, меню закрывается.
3. **Given** меню приоритетов открыто, **When** пользователь нажимает вне меню или клавишу Esc, **Then** меню закрывается, приоритет остаётся прежним.

---

### User Story 2 - Цветовая индикация приоритета (Priority: P2)

Пользователь различает приоритеты по цвету флажка: 1 — серый, 2 — синий, 3 — оранжевый, 4 — красный. Цвет одинаков и для активных, и для выполненных задач.

**Why this priority**: Цвет — то, ради чего приоритет виден в списке с одного взгляда; без него назначение приоритета почти не даёт пользы при просмотре.

**Independent Test**: Создать четыре задачи с приоритетами 1–4 и убедиться, что флажки окрашены в серый, синий, оранжевый и красный соответственно, в том числе после отметки задач выполненными.

**Acceptance Scenarios**:

1. **Given** задача имеет приоритет 2, **When** список отрисован, **Then** её флажок синий.
2. **Given** задача с приоритетом 4 отмечена выполненной, **When** список отрисован, **Then** флажок остаётся красным, а не приглушается вместе с текстом.
3. **Given** у задачи приоритет 1, **When** список отрисован, **Then** флажок серый и не выглядит как активная ошибка или предупреждение.

---

### User Story 3 - Сохранение приоритета и совместимость со старыми задачами (Priority: P3)

Приоритет хранится вместе с задачей: он переживает перезагрузку страницы и перезапуск приложения. Задачи, созданные до появления фичи, получают приоритет 1 и не ломают список.

**Why this priority**: Без сохранения приоритет был бы декорацией; совместимость нужна, потому что в базе уже есть задачи без поля приоритета.

**Independent Test**: Назначить задаче приоритет 4, перезапустить приложение, открыть список и увидеть приоритет 4; открыть задачу, созданную до фичи, и увидеть приоритет 1.

**Acceptance Scenarios**:

1. **Given** задаче назначен приоритет 3, **When** страница перезагружена, **Then** задача по-прежнему имеет приоритет 3 и оранжевый флажок.
2. **Given** в базе есть задача без сохранённого приоритета, **When** список отрисован, **Then** задача показывается с приоритетом 1.
3. **Given** в базе есть задача с некорректным значением приоритета, **When** список отрисован, **Then** интерфейс показывает приоритет 1 и не падает.

---

### Edge Cases

- Попытка назначить приоритет вне диапазона 1–4 (0, 5, пустая строка, текст) — значение отклоняется, приоритет задачи не меняется, пользователь видит сообщение об ошибке.
- Задача удалена в другой вкладке, пока меню приоритетов открыто, — выбор варианта завершается сообщением об ошибке, список перезагружается без удалённой задачи.
- Быстрые повторные клики по разным вариантам меню — применяется один приоритет, список не дублирует задачи.
- Задача без приоритета в базе (старые данные) — трактуется как приоритет 1.
- Приоритет не влияет на порядок списка и на результаты поиска: они остаются прежними.
- Отметка задачи выполненной и обратно не сбрасывает приоритет.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая задача ДОЛЖНА иметь ровно один приоритет из набора 1, 2, 3, 4, где 1 — самый низкий, 4 — самый высокий.
- **FR-002**: Новая задача ДОЛЖНА получать приоритет 1, если пользователь не указал иное.
- **FR-003**: Рядом с каждой задачей в списке ДОЛЖНА отображаться иконка флажка, окрашенная в цвет её приоритета: 1 — серый, 2 — синий, 3 — оранжевый, 4 — красный.
- **FR-004**: Нажатие на иконку флажка ДОЛЖНО открывать меню с четырьмя вариантами приоритета; каждый вариант ДОЛЖЕН быть подписан и показан тем же цветом, что и соответствующий приоритет.
- **FR-005**: Выбор варианта в меню ДОЛЖЕН немедленно применять приоритет к задаче, закрывать меню и обновлять отображение задачи.
- **FR-006**: Закрытие меню без выбора (клик вне меню или Esc) НЕ ДОЛЖНО изменять приоритет.
- **FR-007**: Приоритет ДОЛЖЕН сохраняться между перезагрузками страницы и перезапусками приложения.
- **FR-008**: Задачи, созданные до появления фичи, ДОЛЖНЫ отображаться с приоритетом 1 без ручной миграции данных.
- **FR-009**: Значения приоритета вне диапазона 1–4 ДОЛЖНЫ отклоняться с сообщением об ошибке и без изменения сохранённого значения.
- **FR-010**: Изменение приоритета НЕ ДОЛЖНО менять порядок списка задач: он остаётся по дате создания, сначала новые.
- **FR-011**: Иконка флажка ДОЛЖНА быть доступна с клавиатуры и сообщать текущий приоритет текстом (подпись или всплывающая подсказка).
- **FR-012**: Отметка задачи выполненной и обратная отметка НЕ ДОЛЖНЫ изменять приоритет; цвет флажка ДОЛЖЕН оставаться цветом приоритета.

### Key Entities *(include if feature involves data)*

- **Task (задача)**: существующая сущность списка задач; получает атрибут «приоритет» — целое число от 1 до 4, обязательный, по умолчанию 1. Остальные атрибуты (название, описание, статус выполнения, срок, даты создания и изменения) не меняются.
- **Priority (приоритет)**: справочное значение 1–4 с фиксированными названиями и цветами: 1 — Low (серый), 2 — Medium (синий), 3 — High (оранжевый), 4 — Critical (красный).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для всех четырёх приоритетов флажок отображается в ожидаемом цвете — проверка на 4 задачах даёт 4 совпадения.
- **SC-002**: Назначение приоритета занимает не более трёх действий пользователя: открыть меню, выбрать вариант, увидеть результат.
- **SC-003**: 100% назначенных приоритетов сохраняются после перезагрузки страницы и перезапуска приложения.
- **SC-004**: 0 задач в базе имеют приоритет вне диапазона 1–4 после любых действий пользователя, включая ошибочные попытки ввода.
- **SC-005**: Порядок списка и результаты поиска при назначении приоритета не меняются — проверка до и после назначения даёт одинаковую последовательность задач.

## Assumptions

- Приоритет назначается через меню, а не циклическим переключением по клику: так пользователь выбирает нужное значение одним действием и видит все варианты с подписями.
- Значение 1 — серый (низкий), 4 — красный (высокий); соответствие цветов задано постановкой задачи и не настраивается пользователем.
- Приоритет не сортирует и не фильтрует список в этой фиче; такие возможности могут появиться отдельной задачей.
- Задачи, созданные до фичи, не мигрируются отдельным скриптом: отсутствующее значение трактуется как 1 при чтении.
- Подписи вариантов меню и подсказки остаются на английском языке, как и остальной интерфейс TaskFlow.
- Пользователь один (личный менеджер задач), ролей и прав доступа нет.
