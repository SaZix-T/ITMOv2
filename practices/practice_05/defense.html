AGENTS.md · фрагмент
## Agent Environment (OpenCode) - Rules live in this `AGENTS.md`; OpenCode loads it automatically for the project. - Skills live in `.opencode/skills/<name>/SKILL.md`. - MCP: `opencode.json` starts the local `taskflow` server, exposing the read-only `task_summary` tool. - Hook: `.opencode/plugins/taskflow-check.js` runs `npm test` after source edits and appends the result.
Практика 4 · защита
Среда · 2/5 skill

Skill taskflow-verify

Skill — это инструкция, которая лежит в репозитории и подгружается только по требованию (native skill-tool), а не занимает контекст всегда.

  • Frontmatter: name + description — по описанию агент сам понимает, когда грузить.
  • Контракт: запустить scripts/verify.sh, прочитать PASS/FAIL, показать первое падение, не ослаблять тесты ради зелёного.
устройство · SKILL.md
--- name: taskflow-verify description: Run the TaskFlow verification runner and interpret its PASS/FAIL output. Use after changing backend, database, tests or server wiring... --- ## What I do Execute `scripts/verify.sh` from the repository root... ## How to use me 1. Run: `bash scripts/verify.sh` 2. Read the summary (`VERIFY: OK` / `VERIFY: FAILED`).

Практика 4 · защита
MCP · успешный вызов через MCP Inspector

Успешный сценарий

Inspector проверяет сервер независимо от агента и модели — чисто по протоколу. Снизу — реальный вывод.

$ npx @modelcontextprotocol/inspector --cli node mcp/taskflow-server.mjs --method tools/call --tool-name task_summary --tool-arg status=all
{ "content": [ { "type": "text", "text": " TaskFlow database: .../practice_04/data/taskflow.db total 4 | active 4 | completed 0 | overdue 1 filter=\"all\" -> 4 shown (max 20): - #4 [ ] Dark theme + date (due 2026-12-31) - #3 [ ] Something new (due 0001-01-01) - #2 [ ] Something - #1 [ ] Smoke test" } ] }

Данные — из настоящей базы приложения, а не заглушка. tools/list тем же способом отдаёт описание инструмента.

Практика 4 · защита
MCP · ошибочный вход два сценария

Обработка ошибочного входа

1 · неизвестный status
--tool-arg status=pending { "content": [ { "type": "text", "text": "Invalid status \"pending\". Allowed values: all, active, completed, overdue." } ], "isError": true }

Валидацию делаю сам, а не отдаю на откуп схеме, — чтобы сообщение было понятным человеку.

2 · базы ещё нет
-e TASKFLOW_DB_PATH=/nonexistent/nope.db { "content": [ { "type": "text", "text": "Cannot read the TaskFlow database at /nonexistent/nope.db. Start the app once with `npm start` so the file is created..." } ], "isError": true }

Ошибка не «падает», а возвращает isError:true с инструкцией, что сделать.

Среда · 4/5 hook — автопроверка

Проверка запускается сама — после правки

01
Срабатывает на tool.execute.after для edit / write / apply_patch.
02
Фильтр по путям: только src/ public/ test/ mcp/ scripts/ server.js — правка README тесты не гоняет.
03
Запускает npm test и дописывает результат в output.output — агент видит его в том же ходе.
04
Никогда не падает: красные тесты не отменяют правку, только всплывают в выводе.
реальный вывод после правки src/
[taskflow-check] npm test: PASS (25 passed, 0 failed) # при падении: [taskflow-check] npm test: FAIL (exit 1, N failed) fail 1 AssertionError: ...
