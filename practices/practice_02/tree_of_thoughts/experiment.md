# Tree of Thoughts

- Решение, для которого нужны альтернативы: структура и содержание файла `practices/practice_02/tree_of_thoughts/tests_load.md` (локальная версия для эксперимента ToT)
- Критерии выбора: проверяемость, воспроизводимость, полнота, ясность, соответствие README.md (внешне наблюдаемые альтернативы и конкретные изменения файлов)

## Запрос

Сгенерировать 3 внешне наблюдаемые альтернативы структуры и наполнения файла `tree_of_thoughts/tests_load.md` для нагрузочного тестирования сервиса AI‑помощника ревьюера PR. Каждая альтернатива должна описывать: 3–5 сценариев нагрузки, измеримые пороги и метрики, способ снятия evidence, а также краткую методику и окружение. Альтернативы должны различаться подходом к подаче материала (таблица, карточки сценариев, маппинг требований→тесты). На выходе выбрать одну альтернативу по критериям (проверяемость, воспроизводимость, полнота, ясность, соответствие README.md) и внедрить её только в `tree_of_thoughts/tests_load.md`. Основной `practices/practice_02/tests_load.md` оставить как шаблон без изменений.

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям (проверяемость/воспроизводимость/полнота/ясность/соответствие) |
|---|---|---|---|
| A. «Матрица сценариев» (таблица) | Компактно; легко сверять пороги; хорошо покрывает CASE (REL‑1, API‑1, OUT‑1, SEC‑1, OBS‑1); мало дублирования | Плотный текст в ячейках; начинающим трудно воспроизвести шаги «как запустить»; хуже читается на мобиле | 5/4/5/4/5 (=23/25) |
| B. «Карточки сценариев» (по одному блоку на сценарий со Шагами/Ожиданиями/Evidence) | Высокая ясность; пошаговые действия повышают воспроизводимость; удобно для независимой проверки; легко расширять | Чуть больше объёма; меньше плотности сведений, чем в таблице | 5/5/5/5/5 (=25/25) |
| C. «Маппинг требований→тесты» (по CASE‑правилу: гипотеза, критерии, измерения) | Отличная трассируемость требований; видно обоснование каждого теста | Менее практично для запуска: мало конкретики про профили нагрузки; нужно дочитывать примеры команд | 4/3/4/4/5 (=20/25) |

## Выбор

- Выбранная альтернатива: B. «Карточки сценариев»
- Почему: максимальная ясность и воспроизводимость для независимой команды при сохранении полноты и соответствия README.md; шаги запуска и evidence вынесены явно.
- Как проверим: другая команда по описанию запускает 2 из 5 сценариев без уточняющих вопросов и получает ожидаемые результаты: 1) API‑1 — при `LEN=19000` код 2xx, при `LEN=21000` — 413; 2) OUT‑1 — при `LLM_DELAY_MS=12000` сервис отвечает 504 < 11с без 5xx. Плюс сверка артефактов (логи k6, логи сервиса, метрики/docker stats).
