# R.C.T.F.

- **Role:** Senior QA/Performance инженер, дорабатывающий артефакт «Нагрузочные проверки» для AI‑помощника ревьюера PR.
- **Context:** Учебный сервис с правилами из CASE.md (SEC-1, API-1, REL-1, OUT-1, QA-1, OBS-1). Исходный файл имел один общий сценарий без методики и порогов. Нужен воспроизводимый набор сценариев с метриками и проверкой.
- **Task:** Составить и оформить 3–5 конкретных нагрузочных сценариев с профилями/метриками/порогами, описать методику/окружение и зафиксировать использование AI. Внести изменения в соответствующий файл.
- **Format:** Табличный список сценариев (колонки: профиль нагрузки, метрики/пороги, измерения, evidence), раздел «Методика и окружение», раздел «Как использовали AI»; без общих лозунгов.

## Полный запрос

Role: Senior QA/Performance инженер.

Context:
- Продукт: AI‑помощник ревьюера PR. По одному PR получает diff и возвращает summary, до 3 рисков и список проверок.
- Правила и ограничения: CASE.md — SEC-1 (редакция секретов), API-1 (413 при diff > 20000), REL-1 (таймаут внешнего LLM 10 с), OUT-1 (формат ответа), QA-1 (evidence), OBS-1 (минимальные логи).
- Исходный артефакт: файл «Нагрузочные проверки» с 1 высоким по уровню сценарием; нет явных профилей, порогов и методики.

Task:
1) Разработай 3–5 нагрузочных сценариев, каждый с:
   - конкретным профилем нагрузки и длительностью;
   - измеряемыми метриками (коды, латентность p95/p99, доли ошибок, обращения к LLM‑заглушке);
   - целевыми порогами, выведенными из CASE.md и здравого смысла учебного стенда;
   - методикой измерения и указанием evidence (какое правило проверяем).
2) Добавь раздел «Методика и окружение»: стенд, инструменты (k6/curl/python-заглушка), повторность, отчётность, примеры команд.
3) Добавь раздел «Как использовали AI»: что сгенерировал AI, что уточнили вручную.
4) Сформируй готовый фрагмент для вставки в файл.

Format:
- Верни: таблицу сценариев; «Методика и окружение»; «Как использовали AI».
- Язык: русский. Без маркетинга. Указанные пороги должны быть проверяемы.
