# Ответы на вопросы

1. "Как запустить тесты? Укажи файл-источник."
 Ответ: из каталога `lab/` выполнить `make test` (Makefile делегирует: `$(MAKE) -C demo test`); либо напрямую из `lab/demo/` — тот же `make test`. Цель в `demo/Makefile` запускает `python3 -m unittest -v`. Файл-источник тестов — `demo/test_service.py` (класс `SubscribeTest`, три теста: `test_subscribe`, `test_empty`, `test_duplicate`). Проверено: запуск дал `Ran 3 tests ... OK`.

2. "Что будет при пустом имени подписчика? Подтверди кодом."
 Ответ: будет выброшено исключение `ValueError`. В `demo/service.py`:
 `def subscribe(name):` → `if not name.strip():` → `raise ValueError("empty name")`.
 Проверка идёт по `name.strip()`, поэтому пустая строка и строка только из пробелов (`" "`) одинаково попадают под условие и приводят к `ValueError`. Это же поведение закреплено тестом `test_empty` в `demo/test_service.py` (`with self.assertRaises(ValueError): subscribe(" ")`).

3. "Где реализован unsubscribe? Проверь предпосылку вопроса."
 Ответ: предпосылка неверна — функции `unsubscribe` в `demo/service.py` нет и нигде не реализована. В модуле определена только `subscribe(name)` и множество `subscribers`; удаления подписчика из множества код не выполняет. Отписок в сервисе не существует.

4. "Какая CI-система запускает тесты? Если сведений нет, скажи об этом."
 Ответ: сведений о CI в репозитории нет — ни одной конфигурации CI не найдено (нет `.github/workflows`, нет `.gitlab-ci.yml`, нет `Jenkinsfile`, `.travis.yml`, `.circleci` и т.п.; `git ls-files` не содержит ни одного `.yml`/`.yaml` с описанием пайплайна). Значит, тесты не запускаются никакой CI-системой, а запускаются локально через `make test`. В предоставленных материалах нет ответа про CI, потому что CI здесь не настроен.

5. "Сохраняются ли подписки после перезапуска процесса? Подтверди кодом."
 Ответ: нет, не сохраняются. В `demo/service.py` подписчики лежат в `subscribers = set()` — это изменяемое множество на уровне модуля, то есть в оперативной памяти процесса. Никакой записи в файл, БД или иное постоянное хранилище нет, поэтому при завершении процесса множество теряется и после перезапуска начинается с пустого. В `demo/test_service.py` это подтверждается `setUp`, который просто вызывает `subscribers.clear()` перед каждым тестом.
