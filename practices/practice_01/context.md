## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника: по одному PR на вход получает diff и возвращает: краткое описание, до трех рисков и список проверок. (CASE.md)
- Решение всегда принимает человек; помощник только советует. (CASE.md, SCOPE-1)
- Правила репозитория: SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1. (CASE.md)

### Формат входа и результата

- Вход: diff учебного PR. (CASE.md)
- Результат: OUT-1 — summary, массив risks (<=3) с file, line, evidence, risk; массив checks. (CASE.md)

### Ограничения и запрещённые действия

- SEC-1: перед отправкой в LLM из diff удаляются секреты. (CASE.md)
- API-1: diff > 20000 символов отклоняется с 413. (CASE.md)
- REL-1: таймаут внешнего LLM 10 секунд, ошибка превращается в контролируемый ответ. (CASE.md)
- SCOPE-1: сервис только советует; не пишет код и не выполняет действия в GitHub. (CASE.md)
- QA-1: включаем риск только при наличии evidence из diff или правила. (CASE.md)
- OBS-1: логируются только request_id, длительность и статус; содержимое diff/ответа не логируется. (CASE.md)

### Хороший пример

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```
### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```
### Что пока неизвестно

- Требования к аутентификации/авторизации. (Нет данных в CASE.md)
