# Макеты TaskFlow — общая спецификация

Пять вариантов одного и того же экрана. Отличаются библиотекой компонентов, палитрой,
типографикой и характером. Содержимое и состояния у всех одинаковые, чтобы можно было
сравнить дизайн, а не тексты.

Каждый вариант — самостоятельный статический HTML-файл. Никаких сборок, npm-пакетов и
запросов к API: только выбранная библиотека с CDN, шрифты и немного ванильного JS для
переключения состояний.

## Что должно быть на экране

### Шапка
- Логотип-знак (круг/орбита, только CSS) и название **TaskFlow**.
- Подпись под названием: «учебные задачи».
- Поле поиска с видимой подписью «Поиск» (или sr-only label + placeholder «Найти задачу…»).
- Основная кнопка «Новая задача».

### Сводка
Три показателя: «Всего 8», «Активных 5», «Выполнено 3». Оформление — на усмотрение
варианта (плашки, строка телеметрии, колонка сбоку).

### Фильтры
Переключатель: «Все (8)», «Активные (5)», «Выполненные (3)». Активный пункт визуально
выделен. Это кнопки, а не ссылки.

### Список задач (состояние `list`)
Четыре карточки в таком порядке:

1. не выполнена — «Сдать лабораторную по ИИ» — «Практика 8: новый фронтенд и клиентские
   тесты» — срок «21 ноя» — создана «18 ноя»;
2. не выполнена — «Подготовить доклад по физкультуре» — «Слайды и текст в Typst, проверить
   шапку» — срок «24 ноя» — создана «17 ноя»;
3. не выполнена — «Разобрать конспект по матанализу» — «Пределы и непрерывность, задачи
   1-14» — срок «сегодня» (выделен цветом предупреждения) — создана «16 ноя»;
4. выполнена — «Заполнить БГД по осознанному потреблению» — «Категории, цифры и
   сокращения» — срок «12 ноя» — создана «10 ноя». Заголовок зачёркнут и приглушён,
   чекбокс отмечен.

У каждой карточки: чекбокс с подписью для скринридера, заголовок, описание, срок,
дата создания и две кнопки — «Изменить» и «Удалить» (удаление визуально опасное).

Над списком или в шапке — всплывающее уведомление об успехе: «Задача создана» с кнопкой
закрытия. Оно относится к состоянию `list` и показывает успешный результат сценария.

### Состояние `loading`
Три скелетона карточек (серые блоки) и текст «Загружаем задачи…». Без спиннера на весь
экран: пользователь должен видеть, что список вот-вот появится.

### Состояние `empty`
Заголовок «Задач пока нет», пояснение «Добавьте первую — она появится в этом списке.»,
кнопка «Новая задача».

### Состояние `error`
Заголовок «Не удалось загрузить задачи», пояснение «Сервер не ответил. Проверьте
соединение и попробуйте снова.», кнопка «Повторить».

### Состояние `dialog`
Модальный диалог «Новая задача»:
- поле «Название» — обязательное, подсказка «Например: сдать отчёт по практике»;
- поле «Описание» — многострочное, подсказка «Детали, ссылки, что именно сделать»;
- поле «Срок» — дата;
- внизу «Отмена» и «Создать задачу».

При нажатии «Создать задачу» с пустым названием под полем появляется сообщение
«Введите название задачи» (role="alert"), диалог не закрывается. Если название введено —
диалог закрывается, показывается состояние `list` с уведомлением «Задача создана».
Это демонстрация валидации и успеха, без обращения к серверу.

## Переключатель состояний макета

Внизу слева — панель, которая не является частью интерфейса и явно выглядит как
инструмент ревьювера:

```
МАКЕТ  [ Список ] [ Загрузка ] [ Пусто ] [ Ошибка ] [ Диалог ]
```

Моноширинный шрифт, тёмная нейтральная плашка, кнопки с `aria-pressed`. Нажатие
переключает видимое состояние (`data-view` на `<main>` или скрытие секций).
«Диалог» открывает модальное окно поверх списка.

## Доступность и адаптивность

- У каждого поля есть `<label>`, связанный через `for`/`id`; placeholder не заменяет подпись.
- Фокус виден: обводка 2px цветом акцента с отступом 2px (`:focus-visible`).
- Все действия — настоящие `<button>`; Enter и Space работают.
- Диалог: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, закрытие по Esc и по
  клику вне окна, фокус ставится на поле названия при открытии.
- Контраст текста не ниже 4.5:1; приглушённый текст остаётся читаемым.
- На ширине 375px всё читается: карточки в одну колонку, кнопки не прячутся в hover,
  диалог занимает почти всю ширину, панель макета переносится.

## Общие правила

- Язык интерфейса — русский. Никаких эмодзи.
- Только настоящие компоненты библиотеки: кнопки, поля, карточки, диалог, бейджи,
  чекбоксы. Кастомный CSS — для палитры, отступов, фона и мелких деталей, но не вместо
  компонентов.
- Шрифты — через Google Fonts, с системным fallback.
- Никаких внешних картинок и иконок: знак, звёзды и орбиты рисуются CSS/SVG.
- Внешний вид — тёмная тема с космическим характером, но интерфейс остаётся рабочим
  инструментом, а не постером: текст читается, кнопки очевидны.
