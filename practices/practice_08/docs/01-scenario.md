# Основной пользовательский сценарий

TaskFlow — список личных задач: название, описание, срок и отметка «сделано», всё лежит в SQLite и меняется через REST API.

## Кто пользователь

Студент 2 курса ИТМО. Учёба разложена по неделям: лабораторные, домашки, дедлайны по практикам, подготовка к коллоквиумам. Задачи всплывают где угодно — в метро по дороге на пару, на лекции, вечером дома, — поэтому список открывают и с телефона, и с ноутбука.

Что для него важно:

- добавить задачу за несколько секунд: одно обязательное поле, остальное по желанию;
- видеть срок, а не вспоминать его;
- ничего не потерять: список хранится в базе и переживает перезагрузку страницы и перезапуск сервера;
- понять, что запись точно сохранилась, и не вводить её второй раз.

Экран телефона — около 360 px по ширине, поэтому диалог создания занимает почти весь экран, поля идут в столбик, кнопки не мельче 44 px по высоте.

## Задача пользователя

Собрать все учебные дела в один список и отмечать выполненное, чтобы не держать дедлайны в голове и не искать их по чатам и заметкам. За один заход пользователь добавляет 3–5 задач, отмечает пару сделанных и находит нужную через поиск по слову.

## Основной сценарий

1. **Открывает страницу.** Express отдаёт `index.html` из `public/`, за ним грузятся `style.css` и `app.js`. В области списка до ответа сервера видно «Загружаю задачи…», кнопка «Новая задача» доступна сразу.
2. **Видит список.** `app.js` отправляет **GET `/api/tasks`**. Если вернулся пустой массив — блок «Пока нет задач» и подсказка добавить первую. Если задачи есть — карточки, свежие сверху: сервер сортирует по `created_at DESC`. В карточке название, описание (когда оно непустое), срок и дата создания.
3. **Нажимает «Новая задача».** Открывается модальный диалог на `<dialog>` с тремя полями: «Название», «Описание», «Срок». Фокус сразу в «Названии», Esc и крестик закрывают диалог без запроса.
4. **Заполняет поля.** Название обязательно. Описание можно пропустить. Срок выбирается в `input type="date"` и уходит на сервер строкой `YYYY-MM-DD`; если дату не выбрали, отправляется `null`.
5. **Нажимает «Создать»** (или Enter из поля). Сначала проверка на клиенте: если `title.trim()` пустой, под полем появляется «Введите название задачи», запрос не уходит и ничего не блокируется — можно сразу исправить. Если название есть, кнопка блокируется и меняет текст на «Сохраняю…», уходит **POST `/api/tasks`** с телом `{title, description, due_date}`.
6. **Сервер отвечает 201** и объектом задачи. Диалог закрывается, поля очищаются, строка поиска сбрасывается (иначе новая задача может не попасть в отфильтрованный список и покажется потерянной), затем снова **GET `/api/tasks`**.
7. **Видит новую задачу первой.** Сервер отдаёт список по `created_at DESC`. Дополнительно новый объект подставляется в начало локального массива: `created_at` хранится с точностью до секунды, и у двух задач, созданных подряд, время может совпасть.
8. **Отмечает задачу выполненной.** Клик по чекбоксу отправляет **PUT `/api/tasks/:id`** с `{completed: 1}`. В ответ приходит обновлённая задача, она заменяет старую в массиве, список перерисовывается целиком. Заголовок становится зачёркнутым и приглушённым, чекбокс отмечен. Снятие галочки — тот же запрос с `completed: 0`.
9. **Или удаляет задачу.** «Удалить» → подтверждение → **DELETE `/api/tasks/:id`** → карточка исчезает. Если задач не осталось, снова показывается «Пока нет задач».

В текущем `public/` форма стоит прямо в потоке страницы, тексты английские, а состояний всего три: загрузка, пустой список, ошибка. По этому сценарию форма переезжает в диалог, добавляются блокировка кнопки на время запроса и отдельный блок ошибки с повтором. API менять не нужно — все перечисленные запросы уже есть в `src/routes/tasks.js`.

## Состояния интерфейса

| Состояние | Когда возникает | Что видит пользователь |
|---|---|---|
| Загрузка | после открытия страницы и перед каждым `GET /api/tasks` | текст «Загружаю задачи…» на месте списка, кнопка «Новая задача» активна |
| Пустой список | `GET` вернул `[]`, поиск пустой | «Пока нет задач» и кнопка «Добавить первую» |
| Успешное создание | `POST` вернул 201 | диалог закрылся, новая карточка сверху, поля пустые |
| Отправка | запрос `POST`/`PUT` ещё не завершился | кнопка неактивна, текст «Сохраняю…», повторный клик и Enter игнорируются, диалог не закрывается |
| Ошибка валидации | название пустое или из одних пробелов | сообщение под полем «Введите название задачи», поле подсвечено, фокус в нём, запроса нет |
| Ошибка сервера | `POST`/`GET`/`PUT` вернул 500 или сеть недоступна | блок с текстом ошибки, кнопка «Повторить», которая повторяет тот же запрос; введённые данные в диалоге сохраняются |
| Задача уже удалена | `PUT` или `DELETE` вернул 404 | сообщение «Задача уже удалена» и перезагрузка списка |
| Поиск без результатов | в строке поиска есть текст, `GET /api/tasks?q=…` вернул `[]` | «Ничего не найдено» и кнопка «Сбросить поиск» — это не то же самое, что пустой список |

## Что должно получиться

- На пустой базе страница показывает «Пока нет задач», а не пустой экран и не бесконечную загрузку.
- Кнопка «Новая задача» открывает диалог, курсор стоит в поле «Название», Esc закрывает диалог.
- Отправка с пустым названием или названием из пробелов не создаёт запрос: в DevTools нет `POST`, под полем видно сообщение.
- После «Создать» карточка появляется сверху без перезагрузки страницы; в Network видно `POST /api/tasks` → 201 и следующий за ним `GET /api/tasks` → 200.
- Двойной клик по «Создать» и повторное нажатие Enter во время запроса дают ровно один `POST`.
- Чекбокс меняет вид карточки (зачёркнутое название, приглушённый цвет) и после F5 состояние сохраняется — значит, ушёл `PUT` и значение легло в базу.
- При остановленном сервере или ответе 500 видно сообщение и кнопку «Повторить»; после запуска сервера повтор срабатывает и список загружается.

## Что не входит в сценарий

- Авторизация и регистрация: API не знает пользователей, у базы один владелец.
- Несколько списков или проектов с разделением задач.
- Совместная работа и общий доступ к задачам.
- Уведомления, напоминания и письма о дедлайнах.
- Повторяющиеся задачи, подзадачи, вложения, офлайн-режим.
