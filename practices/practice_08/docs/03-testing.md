# Клиентские тесты

## Стек и запуск

- `@playwright/test` 1.65, Chromium.
- Конфиг: `playwright.config.js`. Тесты лежат в `test/client/`.
- `npm run test:client` — все клиентские тесты.
- `npm test` — серверные (`node:test`) и клиентские подряд.

Playwright сам поднимает `node server.js` на порту 3123 с отдельной базой
`data/e2e.db`; `globalSetup` удаляет её перед прогоном. Тесты идут в один воркер,
чтобы не делить базу.

## Как подменяются ответы сервера

`test/client/helpers.js` перехватывает `**/api/tasks**` через `page.route` и ведёт себя
как настоящий сервер:

- те же поля объекта: `id`, `title`, `description`, `completed`, `due_date`,
  `created_at`, `updated_at`;
- те же статусы: `201` на создание, `400` на пустой `title`, `404` на отсутствующую
  задачу, `500` на имитацию сбоя;
- поиск `?q=` фильтрует по `title` и `description`, как `db.search()`;
- опции задержки (`getDelay`, `postDelay`) и ошибок (`getFailures`, `postError`,
  `putError`, `deleteError`) включают нужное состояние.

Каждый вызов записывается в `calls`, поэтому тест может проверить метод, путь и тело
запроса — например, что во время ожидания ушёл ровно один `POST`.

## Что проверяется

| № | Тест | Что доказывает |
|---|---|---|
| 1 | карточки, счётчики, выполненная задача | список и сводка строятся из ответа API |
| 2 | загрузка | скелетоны видны до ответа, потом список |
| 3 | пустой список | пустое состояние вместо пустого экрана |
| 4 | ошибка загрузки и «Повторить» | сообщение и повторный запрос |
| 5 | создание через диалог | фокус в поле, `POST` с телом, тост, карточка первая |
| 6 | пустое название | сообщение под полем, `aria-invalid`, `POST` не уходит |
| 7 | двойная отправка | во время ожидания второй `POST` не появляется |
| 8 | ошибка сервера при создании | сообщение в диалоге, данные сохранены, повтор работает |
| 9 | отметка выполненной | `PUT {completed:1}`, зачёркивание, счётчики |
| 10 | удаление | диалог подтверждения, отмена без `DELETE`, подтверждение удаляет |
| 11 | задача уже удалена | `404` → сообщение и удаление карточки |
| 12 | поиск | `?q=` уходит на сервер, пустой результат и сброс поиска |
| 13 | фильтры | «Активные»/«Выполненные» и пустая выборка |
| 14 | клавиатура и Esc | Enter открывает диалог, Esc закрывает, фокус возвращается |
| 15 | видимый фокус | при Tab у кнопки обводка 2 px |
| 16 | узкий экран 390 px | нет горизонтальной прокрутки, действия видны, диалог влезает |
| 17 | полный сценарий с настоящим API | создание, выполнение, перезагрузка, удаление |

Тест 17 — единственный без подмены: он работает с настоящим Express и SQLite,
поэтому подтверждает интеграцию, а не только вёрстку.

## Проверка качества тестов

1. Каждый тест сопоставлен с действием пользователя и видимым результатом: карточка,
   сообщение, счётчик, фокус, тост.
2. Формат ответов подмены совпадает с реальным API — тест не пройдёт, если фронтенд
   начнёт ждать другое поле.
3. Проверка «сломай и посмотри»: временно убрали показ сообщения об ошибке создания
   (`el.dialogError.hidden = false`), запустили тест №8 — он упал на
   `expect(dialog-error).toBeVisible()`. Код вернули, тест снова зелёный.
4. Два полных прогона подряд: `17 passed` в каждом.

## Что пришлось чинить в тестах и коде

- у `<dialog>` не было `data-testid` — добавили, иначе тесты не находили окно;
- в скрытом списке оставались старые карточки — очищаем `#task-list` при смене состояния;
- возврат фокуса после закрытия диалога иногда проигрывал гонку с браузером —
  сделали `restoreDialogFocus()` через `requestAnimationFrame` с запасной кнопкой;
- первый тест ловил таймаут загрузки Google Fonts — в тестах шрифты блокируются,
  ожидание переведено на `domcontentloaded`.
